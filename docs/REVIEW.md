# 사용자 검토 항목

v0를 진행하면서 엔진이 임의로 정한 해석과 사용자가 결정할 일을 모았습니다. 항목마다 **현재 처리**를 적어 두었으니, 그대로 둘지 바꿀지만 정하면 됩니다. 결정하면 `docs/DECISIONS.md`에 옮기고 이 파일에서는 지웁니다.

- 작성: 2026-11-18
- 우선순위: **A** = v1 화면 전에 정해야 함, **B** = 출시 전까지, **C** = 나중에 해도 됨
- 결정 완료: 1-1 계약 전 판정, 2-1 전세 담보별 한도 → D-15 ("가능 + 안내")

## 1. 제품 결정

| # | 우선 | 항목 | 현재 처리 | 선택지 |
|---|---|---|---|---|
| 1-2 | B | **계약일을 모를 때 호당 한도.** 2025-06-27 이전 계약은 한도가 더 큽니다(구입 4억, 전세 3억/2억). | 계약일을 모르면 현행 한도(구입 3.2억, 전세 2.5억/1.6억)로 계산합니다. | ① 그대로 둔다 ② 계약일을 입력할 때만 예전 한도 안내 |
| 1-3 | B | **규제지역을 모를 때 LTV.** 수도권 외 지역에서 규제지역 여부를 모르는 경우 | 80%로 계산합니다(유리한 쪽). | ① 그대로 둔다 ② 보수적으로 70% ③ 결과에 "규제지역이면 70%" 안내 |
| 1-4 | C | **금리 범위 표시.** 구입자금은 대출기간(10~30년)에 따라 금리가 다릅니다. | 결과의 `rateRange`는 모든 기간의 최저~최고 금리이고, 우대는 자녀·청약저축만 반영합니다. 금리 방식 가산(+0.1~0.3%p)은 반영하지 않습니다. | ① 그대로 둔다 ② 기간을 입력받아 금리 하나만 보여 준다 |

## 2. 정책 해석 (소스에 수치나 입력이 없는 부분)

| # | 우선 | 항목 | 현재 처리 | 확인 방법 |
|---|---|---|---|---|
| 2-2 | B | **"다자녀" 기준.** 우대금리표에 다자녀 0.7%p, 2자녀 0.5%p, 1자녀 0.3%p가 있습니다. | 3자녀 이상을 다자녀로 봤습니다. | 원문에서 다자녀 정의 확인 후 `docs/sources/`에 추가 |
| 2-3 | B | **민법상 성년 세대주.** 소스에 나이 수치가 없습니다. | 판정하지 않고 `manualChecks`로 안내만 합니다. | 성년 나이를 소스에 추가하면 조건으로 바꿀 수 있음 |
| 2-4 | B | **생애최초의 "기금 구입·중도금 대출 이력 없음".** 입력 항목이 없습니다. | `manualChecks`로 안내만 합니다. | 입력 위저드에 질문을 하나 추가할지 결정 |
| 2-5 | C | **자녀 수.** 미성년 자녀만 세는지, 자녀 출생일 기준이 있는지 | 입력한 자녀 수를 그대로 셉니다. | 원문 확인 |
| 2-6 | C | **결혼 예정일이 이미 지난 경우** | 결혼 예정(`planned`)인데 날짜가 기준일보다 이전이면 신혼 조건이 `false`(불가)가 됩니다. | 화면에서 "혼인신고 했나요?"로 다시 묻는 게 자연스러움 |

이미 STATUS에 있던 항목(구입자금 "만 30세 미만 단독세대주 제외" 생략, 구입자금 DTI는 `manualChecks`)은 그대로 유지합니다.

## 3. 골든 케이스 검토

`docs/golden-cases.md`는 아직 초안입니다. 엔진은 모든 케이스를 통과하지만, 기대값 자체가 맞는지는 사람이 봐야 합니다. 특히 아래를 확인해 주세요.

- [ ] P11·J10: 입력 "모름"이어도 예상 한도를 보여 주는 게 맞는지 (현재 보여 줌)
- [ ] R04: 1인 소득 기준이면 소득 구간과 무관하게 최고 행(7천 초과~8.5천) 금리에 +0.3%p (현재 4.15%)
